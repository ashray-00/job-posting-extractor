# PROJECT.md — Job Posting Extractor

## What this repo is
A fine-tuned small language model that converts unstructured job postings into strict JSON
conforming to `schema/posting.py`. Success = higher field-level F1 than an 8B model using
few-shot prompting + constrained decoding, at lower cost per 1,000 documents.

## Rules for all contributors, human and AI

1. **NEVER modify `data/eval/` or `src/metrics.py`.** These are frozen. If a fix is genuinely
   needed, create `eval_v2` and re-run every prior result. Never edit in place.
2. **NEVER use remembered CLI flags or API parameter names.** Run `--help` or `pip show` and use
   what it prints. This stack ships breaking changes monthly.
3. **Every evaluation run writes one JSON file to `results/`** with the full record specified
   below. If a run isn't in `results/`, it didn't happen.
4. **`schema/posting.py` is the single source of truth.** The JSON Schema for constrained
   decoding, the validator for filtering, and the types used by metrics all derive from it. Never
   hand-write a second copy of the schema anywhere.
5. **Empty list `[]` means "none stated" on list fields. `null` is forbidden on list fields.**
   On scalar fields, `null` means "not stated in the document" and is a *correct answer*.
6. **No network calls in `src/metrics.py`, `src/filter.py`, or `schema/`.** These must be pure and
   testable offline.
7. **Every function that touches money or GPU time logs what it spent.**

## Metric definitions
- `schema_valid_rate` — fraction of outputs that parse and validate against the Pydantic model.
- `field_f1[field]` — per-field precision/recall/F1 after normalisation. A prediction of `null`
  where gold is `null` counts as a true negative, not a miss.
- `macro_f1` — unweighted mean of `field_f1` across all fields.
- `hallucination_rate` — fraction of (example, field) pairs where prediction is non-null but gold
  is null.
- `omission_rate` — fraction where prediction is null but gold is non-null.
- `exact_record_match` — fraction of examples where every field is correct.
- `skill_set_f1` — set-level P/R/F1 on `required_skills` after ESCO normalisation.

Aggregation: macro-F1 averages over FIELDS, not over examples. Per-field F1 is micro-averaged
over examples within that field.

## Data provenance
- Djinni (`lang-uk/recruitment-dataset-job-descriptions-english`), MIT — English/Russian IT
  postings, real text.
- EMSCAD (Kaggle `shivamb/real-or-fake-fake-jobposting-prediction`) — salary-bearing postings +
  partial gold structured fields.
- Synthetic German — generated by [teacher model], distributions sampled from
  `lukebarousse/data_jobs`.
- ESCO — skill and occupation vocabulary.
`data_jobs` is a distribution reference ONLY. It contains no description text and is never used
as extraction input.
